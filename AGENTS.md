# AIUI Developer Tools & Skills

This repository provides developer tools, a scaffolding CLI, AI agent skills, sample apps, and documentation for building applications on **AIUI**. See `README.md` for the full overview.

> **What this file is.** This root `AGENTS.md` is Cursor Cloud / cross-tool **agent operating guidance** — what a Cloud VM can and cannot run. It is deliberately *not* an agent manifest. Those live in `samples/*/AGENTS.md` and the scaffold template. The form AIUI Studio validates on upload is the Identity one (`# Agent Manifest` → `## Identity` → `- **Name**:`); five of the nine manifests here carry it, the scaffold template and three samples still do not. [The Open Agent Format spec](documentation/1-framework/open-agent-format/agents.md) documents a third shape (`# Agent: <name>`) that Studio rejects — no manifest here follows it, and rewriting one toward it breaks the upload. Repository authoring conventions (checks, `.ink`, docs, packaging) live in `CLAUDE.md`; this file only covers the Cloud VM environment.

## Cursor Cloud specific instructions

This is primarily a tooling + samples + documentation repository. What is actually runnable inside a Cloud VM is limited, so keep expectations scoped:

- **`packages/create-aiui-agent` (the runnable application)** — a zero-dependency Node.js CLI that scaffolds a new AIUI agent project from `packages/create-aiui-agent/template/`. Run it from a scratch dir so it does not dirty the checkout, resolving the repo root first (do not use `$OLDPWD` — that is whatever directory you happened to be in): `repo=$(git rev-parse --show-toplevel) && cd /tmp && node "$repo/packages/create-aiui-agent/index.js" my-agent`. It creates `my-agent/` in the current working directory and substitutes `{{PROJECT_NAME}}` placeholders. It refuses to run with no argument (exit 1) or if the target dir already exists. This is the best "hello world" to verify the environment. (The scaffolded project's `package.json` has no `scripts`, so `npm start` there just reports `Missing script: "start"` — running the generated app needs the external device runtime below.)
- **Checks: run `npm test`, but it is not the whole CI gate.** It runs `node scripts/ci/validate.mjs`, a dependency-free validator with seven checks: `json`, `syntax`, `samples`, `whitespace`, `tests`, `pack`, `links`. `tests` runs the real suite in `test/` on `node:test` (`test/locale.test.js`, 21 passing at the time of writing). Run a subset by name, e.g. `node scripts/ci/validate.mjs json links`. There is no ESLint/Prettier config, so formatting is not linted — but this is a genuine test suite, not a placeholder. CI (`.github/workflows/pr-checks.yml`, which the publish workflow also calls) has a third job, `scaffold`, that `npm pack`s `packages/create-aiui-agent`, installs the tarball, drives the installed binary, and asserts the generated files. `validate.mjs` does none of that, so a `files` / `.npmignore` / bin-packaging regression passes `npm test` and still fails CI. For changes to that package, also run the pack-and-install path locally, or rely on the `scaffold` job.
- **`pack` needs network; the other six checks are offline.** The `pack` check fetches `@yodaos-pkg/aix-cli` from npm and packs all 8 samples. It succeeds when the VM has network (verified: 8/8 packed here), but on a network-restricted VM it fails for reasons unrelated to your change. To validate a non-packaging change offline, run `node scripts/ci/validate.mjs json syntax samples whitespace tests links`.
- **Dependencies: `npm ci`, never `npm install` at the root.** Nothing here needs installing — the root `package.json` declares no dependencies and the validator is dependency-free. `npm ci` is a safe no-op (installs nothing, creates no `node_modules`, leaves the lockfile untouched). Do **not** run `npm install` at the root: the committed `package-lock.json` is orphaned residue (`name: jsui`, ~19 `vitepress`/`vue` entries, no matching deps and no `.vitepress/` config), and `npm install` reconciles it — silently rewriting the tracked lockfile from 88,560 bytes to 222 and leaving an unexplained ~88 KB deletion in your diff.
- **Samples do not run in the VM, but they are validated here.** `jsui start` / the generated template target the external AIUI/`jsui`/`aix` device runtime for AI glasses, which is not available — you cannot launch a sample. You *can* build and inspect them: `npm test` packs every sample via `aix-cli` (see the `pack` caveat above), and `npx --yes @yodaos-pkg/aix-cli@0.8.2 pack ./samples/<name> -o out.aix --engine '^0.14.0'` packs one on demand.
- **Design preview** — `design/monochrome/preview-green.html` is a self-contained static HTML file (no build step); open it directly in a browser if you need to view the design tokens.
